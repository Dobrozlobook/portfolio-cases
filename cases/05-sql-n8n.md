# Приём заказов через n8n и Supabase

Демо-проект на тестовых данных (блюда и заказы вымышленные).

## Задача

Принять заказ по HTTP-запросу, записать его в PostgreSQL и сразу вернуть отправителю пять последних заказов с суммой по каждой строке.

## Решение

Сценарий в n8n из четырёх блоков:
Webhook → INSERT → SELECT с JOIN → Respond to Webhook.

Стек: n8n (Docker), Supabase (PostgreSQL), SQL.

## Как это работает

1. На webhook приходит POST с JSON: `dish_id`, `qty`, `order_date`.
2. Параметризованный `INSERT ... RETURNING` записывает заказ в таблицу `orders`.
3. `SELECT` с `JOIN` по таблице `dishes` считает `line_total = qty * price` и берёт последние 5 заказов (`ORDER BY order_id DESC LIMIT 5`).
4. Ответ уходит отправителю запроса в формате JSON.

## Что здесь важно

- Значения передаются параметрами (`$1, $2, $3`), а не склейкой строк.
- Подключение через session pooler Supabase (работает по IPv4).
- Пароль хранится только в credentials n8n: ни в коде, ни в git.
- Запись проверена прямым `SELECT` в базе; тестовые строки удалены через `DELETE ... WHERE`.

## Ограничения

- В тестовой базе отключена проверка SSL-сертификата; для рабочей среды подключается CA-сертификат Supabase.
- Нет валидации входных данных и авторизации webhook; следующим шагом добавил бы проверку полей и секрет в заголовке.
- Уровень SQL: базовый (SELECT, JOIN, GROUP BY, INSERT, UPDATE, DELETE).
