# Ядро расчёта меню: рейтинг блюд и недельное меню

## Задача

Сеть вендинговых холодильников хочет собирать недельное меню по данным, а не «на глаз», и снижать долю списаний. Это тестовое задание из трёх этапов: сначала разбор и проверка данных, затем рейтинг блюд и заполнение меню, затем инструкция и тесты, чтобы ИИ-агент заказчика повторял расчёт без моего участия.

## Как устроено

1. **Данные.** Excel-акты приготовления и списаний за три месяца, около 90 файлов из учётной системы. Папка с актами только для чтения, вручную файлы не правятся.
2. **Разбор.** Код читает акты, находит колонки по тексту заголовка (в разных актах они сдвинуты), берёт дату из названия файла, суммирует повторы кодов, пропускает пустые строки и дубли файлов.
3. **Сверка.** Суммы по строкам сравниваются с итогами актов и с отчётом заказчика. Итоги совпали до единицы. Все исключения (дубли, другие единицы измерения, нулевая себестоимость) попадают в журнал.
4. **Расчёт.** Выпуск, списания и доля списаний по блюдам. Правила и пороги лежат в конфиге (JSON), а не в коде.
5. **Результат (в работе).** Рейтинг блюд по категориям и недельное меню: для каждого блюда указано, почему оно выбрано, и есть запасной вариант.
6. **Передача.** Код, конфиг, инструкция запуска, skill для ИИ-агента заказчика и проверочные тесты.

## Стек

Python, pandas, openpyxl, pytest, JSON-конфиг, виртуальное окружение (venv), Git (ветки, Pull Request), VS Code.

## Что было сложно

- **Данные.** Структура актов разная, колонки сдвинуты. Решение: искать колонки по тексту заголовка, а не по номеру.
- **Определения.** Что считать списанием, как учитывать недельные акты, какую единицу измерения брать. Спорные правила записаны в конфиге и журнале, а не зашиты в код.
- **Честные границы.** Если данных не хватает (например, нет разбивки по точкам), расчёт этого не придумывает и пишет в расшифровке ограничение.

## Результат на сегодня

Разбор и сверка данных завершены и проверены. 11 автоматических тестов проходят. Справочник блюд, рейтинг и недельное меню в работе.

## Как работаю

- Код пишу в VS Code вместе с ИИ-ассистентом (Claude Code) в режиме ручного подтверждения: перед каждым изменением и командой он спрашивает разрешение. Результат проверяю сам: запускаю тесты и сверяю суммы.
- Реальные данные заказчика остаются на моём компьютере и в репозиторий не попадают.
- В приватном репозитории заказчика работаю по схеме «задача (Issue) → отдельная ветка → Pull Request → проверка владельцем». Первый Pull Request приняли без замечаний.
